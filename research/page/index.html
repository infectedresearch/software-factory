  • It made real value. 77 genuine bug fixes (1 high, 31 medium, 45 low severity) survived review and the full test suite — about 98 hours of senior-engineer work by our estimate — for ≈$493 of tokens (≈$6 per real fix).
  • Focus was the lever. One broad agent loop had 30% of its commits kept. Fourteen narrowly scoped agents: 89%.
  • Review was the real work. 13 commits needed fixing before they could merge; several would have shipped new bugs (one would have started logging passwords). About 1 in 7 claimed fixes weren't real bugs.

What we did

We pointed 14 Grok 4.7 coding agents at our production codebase — Twitch AI agents, a streaming studio, overlays, auth, games, a public API — each confined to one area, each on its own branch, looping find one real bug → fix it with a test → commit until the credits ran out. Instructions and policy prohibited deployment, secret access, and editing their own rules. Then Claude Opus 5.5 reviewed every commit, we corrected accepted changes, merged the approved work onto current master, and ran the full test suite.

Focus changed everything

The first run was one agent with a broad prompt. It drifted into busywork: "tests" that read source files as text, plus helper code only those tests used. Splitting the work into narrow lanes with a stricter gate moved the keep rate from 30% to 89%.

What the value is

Every integrated commit was classified (security, user-facing bug, reliability, test, minor), with a rough estimate of how long a senior engineer would need to find and fix it. Against a blind spot-check by separate AI reviewers the classifier agreed on 10 of 11 classes and 9 of 11 "is this a real bug" calls, leaning slightly generous. The biggest wins were in the overlay manager and stream services: refunded redeems that still played, a chat listener that died on one bad message, speech silently skipped. Security-relevant fixes are counted here but described only by category until they are live.

Where it went wrong

  • Overclaiming. 14 of the 100 integrated fixes address something no real input can trigger, and 9 more are real but minor. Commit messages read like every change fixed a bug.
  • Fixes that break things. The reviewer caught 13, several by running a repro: a 5-second full-table scan on every tip, a chat clipper that lost 100 of 101 messages, filter fixes that opened new bypasses.
  • Duplicate work. A lane restarted fresh and re-fixed bugs the earlier run had already fixed (3 commits superseded).
  • Shared state. Parallel fix agents used git's stash, which all worktrees share, and swapped each other's work. Nothing was lost, but forbid it.

Throughput

186 passes; a commit-landing pass took about 8 minutes. 30M fresh and 629M cached tokens for writing (≈$391), ≈$19 for the AI review, ≈$82 for supervision, integration and this write-up. The agents wrote 15,982 lines; 11,339 survived into the integration branch, two-thirds of them tests.

Verdicts per lane

Lane 0 is the first, broad run.

Method, briefly

  • Each lane: own git worktree and branch, a one-paragraph focus, one commit per pass, at most 300 production lines.
  • External prompt, command-pattern policy and gate restrict deployment, service control, network commands, secrets and agent-behaviour files. These are workflow controls, not an OS sandbox.
  • Per-pass gate: compile, forbidden paths, all Node tests and related Python tests, counting only failures that are new versus the base commit.
  • Every 45 minutes: all lanes merged onto current master, full suite run, new failures bisected back to the lane that caused them.
  • After the run: AI review of every commit, blind spot-check of a random sample, fixes, hand-resolved conflicts, full suite on the result. Criteria for "value" were written before the results were read.

Caveats

  • One night, one codebase, one writer model, no human control group. Value labels and hour estimates are AI judgements, calibrated on a small sample.
  • The command-pattern policy does not prevent arbitrary code from accessing the host or network. Scoped-lane results are observational, not a randomized comparison.
  • About 181 tests already fail without production secrets, so some areas were barely tested by the gate.
  • Security findings are described by category only until fixed in production.
  • Status: human sign-off operator approved the high-risk brief (21 of 24 kept); other changes accepted on AI review, blind spot-check and suite comparison; production deployed 2026-10-27; live smoke checks passed; research analysis preliminary. Value counts once it is live and not reverted.

Production release and validation

The approved release is deployed. Production commit 9a5e6198f4f9; Studio edge release 20261027T020402Z, 27 October 2026. All 211 managed edge artifacts match the release. The landing-page asset was hash-verified separately. All 40 supervised lab services, plus clipper web and worker, restarted with new process IDs.

Validation: the final signed-off Python comparison found 181 baseline failures and 174 candidate failures, with zero new failures. All 1,123 Node tests passed; 18 focused tests passed after merging two concurrent master commits; the ship gate also passed 28 browser smoke tests. This is regression-relative validation, not a claim that every test passed.

Live checks completed:

  • mobile/web OAuth handoff
  • authenticated Studio browser and chat UI
  • Studio identity canary
  • public landing/tracker/game pages
  • public API OpenAPI schema
  • synthetic follow alert visibly rendered through public overlay

Initial sign-off exclusions: the tips identity change and its partial performance fix; the malformed-duration guard; and the screamhole audio refactor. The headline totals describe that initial release.

Post-review remediation: seven content-filter findings originally delivered as expected-failure tests were fixed in 9b2e14b0 (378 related tests passed). The tips recipient defect was subsequently approved, fixed with an indexed lookup and ambiguous-identity rejection, and deployed in 2b77f12b (351 database/tips tests and 21 migration tests passed). The production index built in 36.2 seconds; three read-only lookup samples took 14–20 ms. The lab stack was restarted after deployment. These follow-up fixes are separate from the overnight accounting snapshot and initial-release value estimates.

Startup observation: username-history backfill held the SQLite writer lock briefly; completed; subsequent sampled service logs had no errors.

Verification limits:

  • OAuth provider credential entry and chat message sending were not exercised
  • No git remote is configured; local master merged and production deployed

The analysis remains preliminary: value and engineer-hours are AI judgments, and token/cost totals reflect the collected accounting snapshot rather than a continuously updated bill for subsequent report edits and rollout work.
